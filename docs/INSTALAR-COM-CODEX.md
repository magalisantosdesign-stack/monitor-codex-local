# Instalação assistida do Monitor Codex Local

Execute este roteiro somente quando o usuário pedir para preparar/instalar esta versão. Preparar a distribuição e testar o pacote não autorizam instalar hooks na conta pessoal.

1. Leia README.md e AGENTS.md. Resolva esta pasta pelo package.json. Confirme que é monitor-codex-local, não a versão NocoBase. Preserve outras instalações; este roteiro não exige NocoBase, Docker, CLI nb, extensões, serviço, autostart ou protocolo.
2. Confira Node.js 24+ e permissões da pasta permanente. Se faltar Node, use o instalador oficial com autorização de sistema quando necessária, sem alterar políticas globais ou remover versões usadas por outros projetos. Não peça senhas/tokens no chat. Explique intervenções humanas e retome após a confirmação real.
3. Confira public/index.html, app.js, app.css e app.js.LEGAL.txt. O pacote pronto dispensa npm install. Se estiver trabalhando só com fontes sem bundle, execute npm ci e npm run build e confirme o resultado; não diga que está pronto antes de verificar.
4. Confira porta padrão 13021 ou config.local.json existente, sem expor segredos. Reutilize a cópia escolhida. Se a porta pertencer a outro app, escolha outra porta livre nessa configuração; não encerre processos de terceiros. Não copie configurações ou cadastros de outra instalação.
5. Resolva a pasta Codex realmente usada pela conta. Use Configurar-Codex.cmd para a instalação interativa, com prévia, teste do comando nas shells, confirmação S e releitura 9/9. Se o pedido explícito autorizar instalação pelo agente, rode primeiro a prévia node scripts/Install-Hooks.mjs, valide o comando com scripts/validate-hook.mjs e só então use --apply, preservando handlers existentes e backup privado. Nunca apague/retire hooks de outras cópias sem pedido. A confiança é uma etapa humana obrigatória no Codex; não a conceda nem altere o revisor de ferramentas. Na CLI a revisão usa /hooks; a localização no aplicativo depende da versão. Se necessário, oriente recarregar o Codex. Sem evento real confirmado, não anuncie que a integração está funcionando.
6. Execute node scripts/Abrir-Monitor.mjs, ou Abrir-Monitor.cmd no Windows. Confira /app-info com service e instanceId dessa cópia, sem imprimir o token efêmero. Abra a página e confira as três abas, tema e cadastro lateral.
7. Para verificar o pacote pronto, use testes isolados com node --test tests/tasks-store-test.mjs tests/app-integration-test.mjs tests/setup-test.mjs tests/hook-command-test.mjs; eles não precisam das dependências de compilação. Se dependências de desenvolvimento já estiverem instaladas, npm test executa a suíte completa. Para conferir a instalação real, combine uma tarefa de teste identificada com o usuário; não envie mensagens a outro chat sem autorização. Confira salvar sem link, reencontrar após recarregar, edição, validação do link, estado por evento real e atualização sem clique. Sem evento real confirmado, registre essa verificação como pendente, sem fabricar status.
8. Confira Uso do Codex e retenção após trocar/remover vínculo. Ausência de fonte não é zero. Não consumir redefinições, comprar créditos, ler transcrições ou escrever no banco do Codex para fazer o teste passar.
9. Teste Encerrar aplicativo por clique e confirmação, verificando saída somente do PID desta cópia; reabra e confira persistência. Fechar aba não significa encerrar. Nunca use taskkill genérico contra Node, Docker ou Codex.
10. Entregue caminho permanente, como abrir/configurar/encerrar, status dos testes e pendências reais. Explique a criação opcional de um atalho na Área de Trabalho conforme o README. Quando o usuário pedir esse atalho, resolva a Área de Trabalho pela pasta conhecida do Windows (incluindo redirecionamento ao OneDrive), aponte para Abrir-Monitor.cmd desta cópia e use sua pasta como diretório de trabalho; não sobrescreva um atalho existente sem conferir o destino. Não criar atalho de Inicializar, publicar na internet, migrar dados ou criar repositório sem pedido.

Ao criar um atalho solicitado, use public/monitor.ico desta instalação em IconLocation, preservando destino e diretório de trabalho de Abrir-Monitor.cmd.

Se uma etapa depender de login, UAC, confiança ou recurso indisponível, termine o trabalho independente, mantenha a pendência explícita e peça só a intervenção necessária. Não trate passagem de tempo como autorização.
