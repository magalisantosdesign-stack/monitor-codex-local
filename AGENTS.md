# Monitor Codex Local — versão independente

Esta pasta é um aplicativo separado. Não alterar NocoBase, Docker, o monitor pessoal ou outras distribuições para preparar/testar este pacote. Não copiar dados, configurações, histórico Git, credenciais, transcrições ou bancos de origem. IDs de exemplo/teste são somente 00000000-0000-4000-8000-... . A licença é MIT e deve preservar o aviso de autoria existente.

O único servidor atende 127.0.0.1, com host/origem exatos da própria porta. Não aceitar wildcard, hosts externos, proxy, acesso remoto ou CORS de outros apps. GET de navegação pode não trazer Origin; sites cruzados e DNS rebinding são recusados. Toda mutação HTTP exige JSON e token efêmero da sessão desta instância, obtido em /app-info com no-store. Comparar bytes e tamanho antes de timingSafeEqual. CSP sem scripts externos, frames, objetos ou CDN. Static serve somente a lista explícita de arquivos; nunca derivar caminho do pedido, servir .local ou dar fallback HTML para APIs.

SQLite em .local/data/tasks.sqlite contém exclusivamente os cadastros próprios: title/project/linkCodex/status e horários. Nunca gravar no banco do Codex. Tarefas são a fonte oficial dos vínculos; não aceitar /linked para cadastrar IDs de fora do banco. Validar campos, tipos, comprimentos, status e UUID no servidor; SQL parametrizado, transações e paginação com revisão. Dado inválido, esquema desconhecido ou corrupção devem preservar arquivos, não substituir dados. Sem exclusão de tarefas nesta versão. Concluir não remove acompanhamento, Stand-by ou histórico.

Sincronizar linked.json e os nomes do histórico a partir das tarefas após cada escrita e ao iniciar. Uma falha na sincronização não desconfirma a escrita SQLite; informar monitorPending e tentar novamente enquanto ligado. Remover/trocar link interrompe coleta daquele ID se nenhum outro cadastro o usa, mas mantém histórico e preferências numéricas. Preservar regras do núcleo: observar somente chats vinculados, não salvar conteúdo, não inferir conclusão por tempo, não forjar contextos, não autorizar ferramentas, não confiar em hooks pelo usuário. Tokens consultam apenas fontes numéricas permitidas; falha não é zero. Cota da conta não é consumo individual.

Abrir-Monitor.cmd inicia somente o processo desta cópia e abre o navegador; não instalar serviço, autostart, protocolo ou extensão. Os CMDs devem usar call node para funcionar também com shims node.cmd e preservar confirmação/erros. Aguardar a conclusão do comando de abertura do navegador, sem detach/unref; falha ou timeout deve manter o endereço visível, devolver erro ao CMD e pausar a janela. Nunca registrar mensagens do sistema ou comandos no diagnóstico de navegador; salvar somente data, código e porta. Encerrar aplicativo pede confirmação humana, persiste e encerra somente seu próprio Node; fechar a aba não encerra. Iniciador deve recusar porta de outra instalação e evitar duplicação. Configurar-Codex.cmd mostra prévia e exige confirmação antes de --apply; preparação do pacote nunca executa esse instalador na conta pessoal. Preservar outros handlers, manter backups privados e exigir revisão de confiança no Codex. Não migrar cadastros/hooks automaticamente da versão NocoBase.

Interface própria React/Ant Design, sem ctx ou API NocoBase, com Tarefas → Monitor Codex → Uso do Codex. Compartilhar o cadastro lateral entre Kanban e Monitor. Bloquear envio duplicado, manter entradas em falha, invalidar consultas antigas e só anunciar escrita após confirmação. Usar tokens de tema e layout responsivo; nenhum segredo em localStorage. Demo ?demo=1 usa dados fictícios e não faz chamadas de API/gravação; o servidor vazio pode estar aberto, mas o demo não cadastra vínculos.

Configurar-Codex.cmd usa o assistente scripts/Configurar-Codex.mjs: mostra o destino e esta cópia, pede S/Sim, instala preservando handlers e confirma os nove eventos pela releitura. Cancelar não escreve hooks. Reporta somente data/código em .local/setup-result.json. Configuração instalada não significa confiança concedida nem evento recebido; nunca inferir essas etapas. /states expõe apenas status/contagem de configuração, sem caminhos, comandos ou conteúdo. O Monitor deve distinguir configuração ausente/incompleta, leitura indisponível e instalação aguardando primeiro evento. Diagnóstico deve indicar a mesma situação e o arquivo consultado, sem alterar a configuração. Testar o próprio CMD em CODEX_HOME fictício, incluindo cancelar, instalar, manter handler preexistente e reinstalar sem duplicar. A versão exibida pela API vem de package.json.

Comando Windows de hook deve funcionar tanto no CMD quanto no PowerShell. Não gerar um executável apenas entre aspas como primeiro token: PowerShell interpreta isso como texto. Usar executável sem aspas quando não houver espaços; para Node em caminho com espaços, usar invocação explícita de PowerShell com literais escapados. Recusar caracteres de interpolação dos shells. O assistente deve testar o comando gerado nas duas shells antes de oferecer a gravação: somente UUID, CODEX_HOME, configuração e dados fictícios em pasta temporária própria, sem ponte desktop; apagar a fixture após o teste. Confirmar o arquivo do evento, não apenas exit code. Ao atualizar o comando, remover somente variantes antigas desta instalação, preservando handlers de outras origens. Uma definição alterada requer nova revisão humana de confiança; não editar hashes confiados nem executar flags de bypass.

Testar com Node 24 em dados/CODEX_HOME/porta isolados; não usar hooks/configurações/perfis/serviços pessoais. Cobrir SQLite, API, CSRF/origem/host, persistência, registro de eventos, uso/histórico, reinício e encerramento do próprio PID, além de conferência visual real no navegador. Diferenciar testes sintéticos da compatibilidade real com o Codex da usuária. Exportar somente package.files e package.json, incluindo bundle/licenças compilados; excluir node_modules/.local/config.local.json/.git e quaisquer fixtures. Atualizar este arquivo quando regras mudarem. A versão NocoBase permanece independente.

Distribuição para GitHub usa uma cópia limpa formada exclusivamente pelo manifesto público, sem copiar o histórico Git do Work Memory. Imagens públicas ficam em docs/images e devem ser capturadas com ?demo=1, inspecionadas visualmente e sem API/dados reais. O verificador aceita somente PNGs nessa galeria, valida links Markdown locais e recusa caminhos pessoais, IDs reais e possíveis credenciais nos textos. Mudanças em documentação e scripts de distribuição devem acompanhar o manifesto. O ZIP Windows é produzido por scripts/zip-release.ps1 a partir de uma exportação deste projeto, respeitando o manifesto, sem sobrescrever pacote existente, com SHA-256. CI testa em Windows/Node 24 com fixtures e nunca instala hooks na conta real nem publica releases automaticamente. Publicar em repositório separado somente com destino e visibilidade definidos pelo usuário.

A suíte node --test deve usar --test-concurrency=1 no Windows para evitar disputa de recursos entre os processos de navegador/instalador e manter os limites de tempo úteis em runners menores. Isso não altera as regras de execução do aplicativo.

O Kanban de tarefas usa fundos suaves por situação em toda a coluna, com cabeçalho mais destacado: cinza para Não iniciado, azul para Em andamento, amarelo para Aguardando, laranja para Pausado e verde para Concluído. Misturar a cor da situação com colorBgContainer do tema para manter legibilidade nos modos claro e escuro; cartões internos preservam o fundo do tema.

A instalação documenta o atalho opcional da Área de Trabalho para Abrir-Monitor.cmd, sem mover o CMD nem configurar autostart. Se o usuário pedir a criação pelo agente, resolver a pasta conhecida Desktop do Windows, preservar atalhos existentes e conferir destino/diretório de trabalho da própria cópia. Mover a instalação exige recriar o atalho e reconfigurar/revisar os hooks.

O ícone público public/monitor.ico usa um círculo azul, verde e roxo com símbolo de terminal, sem números de consumo. Usá-lo no favicon e, ao criar atalhos solicitados, em IconLocation. Servir somente a rota explícita /monitor.ico; o manifesto inclui o ICO e o verificador valida cabeçalho/diretório/frames PNG antes de exportar. Não copiar ícones ou atalhos de perfis pessoais para o pacote.
